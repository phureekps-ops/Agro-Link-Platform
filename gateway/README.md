# AgroLink Gateway สำหรับศูนย์รับนม

โปรแกรมที่ติดตั้งบน **Gateway อุตสาหกรรม** ประจำศูนย์รับนม (แพลตฟอร์มบริหารโคนมแห่งชาติ)
อ่านค่าจากอุปกรณ์ 4 ชนิดแล้วส่งขึ้น AgroLink ด้วยคีย์เดียว:

| อุปกรณ์ | ต่อด้วย | ข้อมูลที่ส่ง | ปลายทางใน AgroLink |
|---|---|---|---|
| เครื่องชั่งนม | RS-232 | น้ำหนักรายสมาชิก (ทีละถัง) | รอบรับนมของ "เวลาที่ชั่งจริง" (เช้า/เย็น) |
| เซนเซอร์อุณหภูมิถังเย็น | RS-485 (Modbus RTU) | °C ทุก 30 วินาที | กราฟถังเย็น + เตือนเกินเกณฑ์ |
| เซนเซอร์ปริมาณนมในถัง | RS-485 (Modbus RTU) | กก. ในถัง | กราฟ + ระบบแนะนำนมเกิน (ถังจะล้นไหม) |
| เครื่องวิเคราะห์น้ำนม | RS-232 / USB | ไขมัน SNF โปรตีน แลคโตส ความหนาแน่น น้ำปน จุดเยือกแข็ง | ผลรายสมาชิก (+ คิดราคาได้ถ้าสหกรณ์เปิด) + เตือนสงสัยน้ำปน |

```
เครื่องชั่ง ──RS-232──┐
เครื่องวิเคราะห์ ─RS-232─┤                    ┌─ หน้าจอรับนมบนแท็บเล็ต (http://<gateway>:8080)
เซนเซอร์ถัง ──RS-485──┼──► Gateway ──────────┤
                      │   (คิว SQLite        └─ 4G/LAN ──► AgroLink /dairy-iot/gateway/events
                      │    ไม่หายตอนเน็ตหลุด)
```

**หลักการสำคัญ**
- ทุกรายการเขียนลงเครื่องก่อน แล้วค่อยส่ง — เน็ตหลุด/ไฟดับก็ไม่หาย และส่งย้อนหลังเมื่อกลับมา
- ทุกรายการมีรหัสไม่ซ้ำ — ส่งซ้ำกี่ครั้ง AgroLink ก็บันทึกครั้งเดียว (น้ำหนักไม่เบิ้ล)
- ใช้ **เวลาที่ชั่งจริง** — นมรอบเช้าที่ค้างในเครื่องแล้วส่งตอนบ่าย ยังลงรอบเช้า
- ชั่งถังเดิมซ้ำไม่ได้ — ต้องยกถังออก (น้ำหนักกลับต่ำกว่า `min_kg`) ก่อนบันทึกถังถัดไป
- สมาชิกที่มีโคในระยะหยุดยา: บันทึกได้ แต่ AgroLink ตั้งเป็น "ปฏิเสธ (ยาตกค้าง)" ให้เจ้าหน้าที่ยืนยัน

---

## 1. เลือกซื้อ Gateway อุตสาหกรรม

ใช้ได้ทุกรุ่นที่รัน **Linux (Debian/Ubuntu) หรือ Docker** เช่น Advantech, Moxa UC, Siemens IOT2050, Teltonika รุ่นที่รองรับ Docker
ตรวจสเปกตามนี้:

| รายการ | ขั้นต่ำ |
|---|---|
| ระบบ | Linux ที่ติดตั้ง Python 3.9+ ได้ หรือรัน Docker ได้ (ARM64/ARMv7/x86-64) |
| ช่องต่อ | RS-232 อย่างน้อย 2 ช่อง (เครื่องชั่ง + เครื่องวิเคราะห์) + RS-485 1 ช่อง — หรือมี USB สำหรับสายแปลง |
| หน่วยความจำ | RAM 1 GB, พื้นที่เก็บ 8 GB (eMMC/SSD ทนกว่า microSD) |
| เครือข่าย | LAN + 4G (ซิม) ในตัว |
| ทนสภาพ | ใช้งาน −20 ถึง 60 °C, ติดราง DIN, ไฟ 9–36 V DC |
| อื่น ๆ | นาฬิกา RTC มีแบตเตอรี่ (เวลาถูกต้องแม้ไม่มีเน็ตตอนเปิดเครื่อง), watchdog |

ติดตั้งในตู้กันฝุ่นกันน้ำ (IP65) ห่างจากจุดล้างถัง และต่อผ่าน UPS เล็ก ๆ

## 2. เตรียมในพอร์ทัลสหกรณ์ (ทำก่อนติดตั้ง)

พอร์ทัลสหกรณ์ › แพลตฟอร์มบริหารโคนมแห่งชาติ › 📡 IoT

1. **➕ เพิ่ม Gateway ให้ศูนย์รับนม** → เลือกศูนย์ → ได้ **คีย์ (แสดงครั้งเดียว)** เก็บไว้ใส่ในขั้นตอนที่ 4
   ห้ามส่งคีย์ทางแชท อีเมล หรือแคปหน้าจอ — คีย์หลุด/เครื่องหาย กด "ออกคีย์ใหม่" คีย์เดิมใช้ไม่ได้ทันที
2. ที่การ์ด Gateway › **➕ เพิ่มช่องอุปกรณ์** ทีละตัว โดย "ชื่อช่อง" ต้องตรงกับ `channel` ในไฟล์ตั้งค่า:
   - เครื่องชั่งนม → `scale1`
   - ถังเย็น → `tank1` (ใส่อุณหภูมิสูงสุด เช่น 4 °C)
   - เครื่องวิเคราะห์นม → `analyzer1`
3. ตั้งค่า › ใส่ความจุถังของศูนย์ และเลือกว่าจะใช้ผลเครื่องวิเคราะห์ **คิดราคาค่านม** หรือไม่ (ค่าเริ่ม = ไม่ใช้)

## 3. ต่อสายอุปกรณ์

| อุปกรณ์ | สาย | ตั้งที่เครื่อง |
|---|---|---|
| เครื่องชั่ง | RS-232 (DB9: 2-RX, 3-TX, 5-GND) — บางรุ่นต้องสลับ 2/3 (null-modem) | เปิดโหมดส่งน้ำหนักต่อเนื่อง (continuous) ถ้ามี |
| เครื่องวิเคราะห์ | RS-232 หรือ USB | เปิดการส่งผลออกทางพอร์ต (print/export) |
| เซนเซอร์ถัง | RS-485 A/B คู่บิดเกลียว ต่อพ่วงหลายตัวได้ ใส่ตัวต้านทาน 120 Ω ที่ปลายสาย | ตั้ง address (slave) ไม่ซ้ำกัน, baud ตรงกับไฟล์ตั้งค่า |

## 4. ติดตั้งโปรแกรม

คัดลอกโฟลเดอร์ `gateway/` นี้ไปไว้ที่ Gateway (USB หรือ `scp -r gateway/ ผู้ใช้@ip-gateway:`) แล้วเลือกวิธีใดวิธีหนึ่ง

### แบบ A — Gateway ที่เป็น Debian/Ubuntu (แนะนำถ้ามี)
```bash
cd gateway
sudo bash install.sh                 # ติดตั้ง + ตั้งให้เริ่มเองเมื่อเปิดเครื่อง (systemd)
sudo nano /etc/agrolink-gw/config.toml   # แก้ port/channel (ดูข้อ 5)
sudo agrolink-gw test-scale          # เทนมลงถังชั่ง ดูว่าตัวเลขขึ้นและ "นิ่ง"
sudo agrolink-gw test-analyzer       # สั่งวัดตัวอย่าง 1 ครั้ง ดูว่าแยกค่าได้ถูก
sudo agrolink-gw test-modbus         # อ่านอุณหภูมิ/ปริมาณนมในถัง
sudo agrolink-gw setup               # วางคีย์จากข้อ 2 (ไม่แสดงบนจอ) — ตรวจว่าทุกช่อง "ผูกแล้ว"
sudo systemctl restart agrolink-gw
```
อัปเดตเวอร์ชัน: คัดลอกโฟลเดอร์ใหม่แล้ว `sudo bash install.sh` ซ้ำ (ไฟล์ตั้งค่า คีย์ และคิวที่ค้างอยู่ไม่หาย)

### แบบ B — Gateway ที่รัน Docker
```bash
cd gateway
docker build -t agrolink-gw:1.0.0 .
mkdir -p data && cp config.example.toml data/config.toml
nano data/config.toml        # แก้ data_dir = "/data", key_file = "/data/device.key" และ port/channel
nano docker-compose.yml      # แก้ devices: ให้ตรงกับช่อง Serial ของเครื่อง
docker compose run --rm agrolink-gw test-scale
docker compose run --rm agrolink-gw setup
docker compose up -d
```
Gateway ที่ไม่มีอินเทอร์เน็ตไปถึง Docker Hub: build บนคอมพิวเตอร์ (`docker buildx build --platform linux/arm64 -t agrolink-gw:1.0.0 --output type=docker,dest=agrolink-gw.tar .`) แล้ว `docker load -i agrolink-gw.tar` ที่ Gateway

## 5. ไฟล์ตั้งค่า (`config.example.toml`)

- **เครื่องชั่ง**: ค่าเริ่มอ่านรูปแบบ `ST,GS,+0012.34kg` (ST = นิ่ง) ถ้า `test-scale` ไม่ขึ้นตัวเลข ให้ดูข้อความจริงจากเครื่องแล้วแก้ `pattern`
  (ต้องมีกลุ่ม `weight`; ถ้าเครื่องไม่บอกว่านิ่ง โปรแกรมดูจากค่าที่ซ้ำกัน 3 ครั้งแทน) เครื่องที่ต้องขอน้ำหนักก่อน ใส่ `request` ตามคู่มือ
- **เครื่องวิเคราะห์**: รองรับ 3 รูปแบบ — `csv` (ระบุลำดับคอลัมน์ใน `fields`), `keyvalue` (`Fat=3.85 SNF=8.40`), `regex`
  ⚠️ ลำดับคอลัมน์ในไฟล์ตัวอย่างเป็นตัวอย่างเท่านั้น ต้องตรวจกับเครื่องจริงด้วย `test-analyzer` ทุกครั้ง
  ผลที่ไม่มีรหัสสมาชิกจะผูกกับสมาชิกที่เลือกอยู่บนหน้าจอ (ภายใน `attach_member_s` วินาที)
- **Modbus**: `register`, `type` (int16/uint16/int32/uint32/float32), `scale` และ `function` (3 holding / 4 input) ดูจากคู่มือเซนเซอร์
  ถ้าเซนเซอร์ให้ปริมาณเป็นลิตร ใส่ `scale = 1.03` เพื่อเป็น กก.; ค่าเพี้ยนมากลอง `word_order = "little"`
- **หน้าจอ**: `ui_pin` ใส่ PIN 4–6 หลักถ้าแท็บเล็ตอยู่ในที่ที่คนนอกเข้าถึงได้

## 6. ใช้งานประจำวัน (เจ้าหน้าที่ศูนย์)

เปิด `http://<ip-gateway>:8080` บนแท็บเล็ต/คอมในศูนย์
1. พิมพ์หรือสแกนรหัสสมาชิก → Enter (เครื่องอ่านบัตร/QR แบบคีย์บอร์ด USB ใช้ได้เลย)
2. เทนมลงถังชั่ง รอ "นิ่ง ✓ พร้อมบันทึก" → กด **บันทึกน้ำหนัก** (หรือ Enter) → ยกถังออก → ถังถัดไป
3. กด **สมาชิกถัดไป**
มุมขวาบนบอกสถานะ: 🟢 ออนไลน์ / 🔴 ออฟไลน์ (เก็บไว้ในเครื่อง) และจำนวนที่รอส่ง รายการที่ AgroLink ไม่รับ (เช่น รอบปิดแล้ว
หรือไม่พบสมาชิก) ขึ้นป้าย "ไม่ผ่าน" — ให้แก้ในพอร์ทัล

## 7. ตรวจปัญหา

| อาการ | ตรวจ |
|---|---|
| เครื่องชั่งไม่ส่งค่า | สาย/ขา 2-3, baud/parity, `agrolink-gw test-scale`, เปิดโหมด continuous หรือใส่ `request` |
| ตัวเลขขึ้นแต่ไม่ "นิ่ง" | `pattern` ไม่มีกลุ่ม stable → ปรับ `stable_tolerance_kg` |
| ช่อง "ยังไม่ได้เพิ่มในพอร์ทัล" | ชื่อช่องในพอร์ทัลกับไฟล์ตั้งค่าไม่ตรงกัน |
| `key_rejected` | คีย์ผิด/ถูกออกใหม่ → `agrolink-gw setup` |
| นาฬิกาเครื่องคลาด | เปิด NTP (`timedatectl set-ntp true`) — รอบเช้า/เย็นใช้เวลาเครื่อง และ AgroLink ไม่รับเวลาที่ล้ำอนาคตเกิน 5 นาที |
| ค้างส่งนาน | `agrolink-gw status`, `journalctl -u agrolink-gw -f` (Docker: `docker compose logs -f`) — ข้อมูลเก่าเกิน 7 วันจะถูกปฏิเสธ |
| พอร์ทัลเตือน "ออฟไลน์" | Gateway เงียบเกินเวลาที่ตั้ง (ค่าเริ่ม 10 นาที) — ตรวจไฟ/เน็ต เตือนจะปิดเองเมื่อกลับมา |

## 8. ทดสอบโดยไม่มีอุปกรณ์จริง

```bash
python3 -m unittest discover -s tests -v          # ทดสอบทั้งหมด (ตัวจำลอง + AgroLink จำลอง)
python3 -m agrolink_gw sim                          # เปิดตัวจำลองเครื่องชั่ง/วิเคราะห์/Modbus ที่พอร์ต 7001-7003
python3 -m agrolink_gw --config config.sim.toml run # ต่อกับตัวจำลอง + backend ในเครื่อง (localhost:4000)
```

## ความปลอดภัย

- คีย์เก็บในไฟล์สิทธิ์ 600 ของผู้ใช้บริการเท่านั้น ไม่อยู่ในไฟล์ตั้งค่าและไม่อยู่ใน Git
- คีย์ Gateway ทำได้เฉพาะ: ส่งข้อมูลรับนม/ถัง/ผลวิเคราะห์ของศูนย์ตัวเอง และอ่านรายชื่อสมาชิกของศูนย์นั้น
- หน้าจอรับนมเปิดในเครือข่ายของศูนย์เท่านั้น อย่าเปิดพอร์ต 8080 ออกอินเทอร์เน็ต ตั้ง `ui_pin` ถ้าจำเป็น
- เปลี่ยนรหัสผ่านเริ่มต้นของ Gateway และปิดบริการที่ไม่ใช้ก่อนติดตั้งที่ศูนย์
